# TestJrpcClntCli の解説

`TestJrpcClntCli` は、`JrpcClntCli` クラス（JSON-RPC クライアントの CLI ツール）の動作をテストするためのクラスです。

特に **「外部依存（ファイル操作、ネットワーク通信、ユーザー入力など）をモック（偽物）に置き換えて、ロジックだけを検証する」** という、単体テストの典型的な手法をとっています。

## 1. 準備：依存関係を「偽物」にする (`mock_deps`)

テスト対象の `JrpcClntCli` は、内部で以下の機能を使っています：
*   `JrpcClient`: 通信を行うクラス
*   `readline`: コマンド履歴の読み書き
*   `os`: ファイル削除など

これらが実際の動作（ネットワーク通信やファイル削除）をしないように、`@pytest.fixture` で「モック（ハリボテ）」に差し替えています。

```python
@pytest.fixture
def mock_deps(self):
    # ... patch(...) as MockJrpcClient ...
    # ottopi0.jrpcclnt.jrpcclnt_cli モジュール内の "JrpcClient" という名前を、
    # 本物ではなく MockJrpcClient という魔法のオブジェクトに置き換えます。
```

これにより、テスト中に `JrpcClient` を呼び出しても通信は発生せず、「呼び出された」という記録だけが残るようになります。

## 2. 各テストメソッドの役割

### `test_init` (初期化のテスト)
*   **目的**: オブジェクト作成時に、正しくURLが設定され、履歴ファイルが読み込まれるかを確認します。
*   **Mockの役割**: `readline.read_history_file` が実際にファイルを読みに行く代わりに、モックが「呼ばれたかどうか」だけをチェックします (`assert_called()`)。

### `test_main_loop_command` (コマンド実行のテスト)
*   **目的**: ユーザーがコマンドを入力したとき、正しく `jrpc_call`（送信処理）が呼ばれるかを確認します。
*   **テクニック**: `patch("builtins.input", side_effect=["cmd1", EOFError()])`
    *   これは「ユーザー入力(`input()`)」を偽装しています。
    *   1回目は `"cmd1"` を返し、2回目は `EOFError` (Ctrl+D を押した状態) を発生させてループを終了させます。
*   **検証**: `jrpc_call("cmd1")` が実行されたかを `assert_called_with("cmd1")` で確認しています。

### `test_main_loop_comment` (コメント処理のテスト)
*   **目的**: `#` 以降の文字がコメントとして無視されるか確認します。
*   **入力**: `"cmd # comment"`
*   **期待する動作**: コメント部分が削除され、`"cmd "` だけが送信されること。

### `test_end_saves_history` (終了時のテスト)
*   **目的**: クライアント終了時(`end()`)に、コマンド履歴が保存されるか確認します。
*   **検証**: `readline.write_history_file` が呼ばれたかをチェックします。

### `test_init_no_history_file` & `test_init_invalid_history_file` (エラー処理のテスト)
*   **目的**: 履歴ファイルが無かったり、壊れていた場合にプログラムが落ちないか確認します。
*   **テクニック**: `.side_effect = FileNotFoundError`
    *   モックのメソッドが呼ばれた瞬間、指定した「例外（エラー）」を発生させます。
    *   これにより、「ファイルが見つからない状況」を人工的に作り出し、コードが正しくエラーハンドリングしているか（クラッシュしないか、ファイル削除を試みるか）をテストしています。

## まとめ

このテストコードは、**「実際に通信やファイル読み書きをさせずに、プログラムのロジック（入力のパース、エラー時の挙動、メソッドの呼び出し順序）が正しいか」** を検証するために書かれています。
