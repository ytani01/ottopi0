# テストプログラムのリファクタリング計画

これまでのテストファイル (`test_01_func_calc.py`, `test_02_func_servo.py`, `test_11_cli_cmd.py`) のレビューに基づき、テストスイート全体のリファクタリング計画を提案します。

## 1. 共有フィクスチャのために `conftest.py` を導入する

-   `tests/conftest.py` ファイルを作成します。
-   CLI クライアントアプリケーションのモック (例: `test_11_cli_cmd.py` の `mock_cli_app` フィクスチャ) のような共有フィクスチャを `conftest.py` に移動します。これにより、CLI テスト全体でモックロジックが一元化され、重複が減少します。
-   必要に応じて、異なるクライアントタイプや設定をサポートするために、これらのフィクスチャを汎用化します。

## 2. テストセットアップのために `pytest.fixture` を標準化する

-   既存の `setup_method` の実装 (例: `test_01_func_calc.py`) をレビューします。単純なケースでは `setup_method` も許容されますが、再利用性、モジュール性、またはモックとの統合の容易さなどの利点がある場合は、`pytest.fixture` への移行を検討します。

## 3. URL 構築ヘルパーを一元化する (CLI テスト間で重複している場合)

-   `test_10_cli_svr.py`, `test_12_cli_bt.py`, `test_13_cli_webui.py` を調査し、URL 構築ロジックの重複を確認します。
-   重複が存在する場合、期待される URL を生成するためのヘルパー関数 (例: `cli_url_builder(host, port, apipath)`) を `conftest.py` または専用のテストユーティリティモジュールに作成します。

## 4. CLI エラーメッセージのアサーションを強化する

-   例外を処理する CLI テスト (例: `test_11_cli_cmd.py` の `test_cli_exception_handling`) をレビューします。
-   `"Done." in result.output` のような一般的なアサーションではなく、CLI が提供するように設計されている場合は、特定のエラーメッセージをアサートすることを目指します。これにより、テストの堅牢性が向上します。
