# Plan01: `EyeState` クラスのパラメータ削減に関する検討

## 1. はじめに

`samples/robot_face_animation.py` に含まれる `EyeState` クラスのパラメータ数削減に関する検討依頼を受けました。
本ドキュメントでは、現状のコードを分析し、パラメータを統合する際の課題を整理した上で、今後の対応方針を提案します。

## 2. 現状の分析

- **`EyeState`クラスの構成**:
  現在 `EyeState` クラスは、主に `openness` (目の開き具合) と `curve` (閉じたときの曲がり具合) の2つのパラメータで目の状態を管理しています。

- **目標状態におけるパラメータの関係**:
  ユーザーの指摘通り、`RobotFace.MOODS` で定義されている各表情の**目標状態**においては、以下の関係が成り立っています。
  - `curve` が `0` のとき、`openness` は `1.0` (目が開いている)
  - `curve` が `0` ではないとき、`openness` は `0` (目が閉じている)
  このため、目標状態だけを見れば、2つのパラメータは相互排他的であり、統合できる可能性があります。

- **アニメーション処理における課題**:
  しかし、表情が変化する際のアニメーション処理に目を向けると、状況は異なります。`RobotFace.update()` メソッドでは、現在の状態から目標の状態へと近づけるために、各パラメータが線形補間 (`lerp`) によって独立して更新されています。

  ```python
  # (抜粋)
  c.left_eye.openness = lerp(c.left_eye.openness, t.left_eye.openness, speed)
  # ...
  c.left_eye.curve = lerp(c.left_eye.curve, t.left_eye.curve, speed)
  ```

  例えば、「目が開いた状態」 (`openness=1`, `curve=0`) から「ウィンクした状態」 (`openness=0`, `curve=1`) へ移行する際、アニメーションの**中間状態**では `openness` と `curve` が同時に `0` でも `1` でもない値（例: `openness=0.5`, `curve=0.5`）を取り得ます。
  この**並行したアニメーション**が、目が滑らかに閉じていきながら、閉じた形が曲線に変化するという自然な表現を実現しています。

## 3. パラメータ統合の検討

`openness` と `curve` を単一のパラメータ（例: `expression`）に統合することを検討しました。
このアプローチでは、アニメーションの中間状態を正しく表現するための、`expression` の値から `openness` と `curve` の両方を導出するマッピング（計算式）が必要になります。

いくつかのマッピングを試みましたが、以下の問題点があり、単純な統合は困難であることが判明しました。
- **表現できない状態の発生**:
  試みたマッピングでは、「目が閉じていて、かつ直線 (`openness=0`, `curve=0`)」という状態をうまく表現できませんでした。
- **複雑性の増大**:
  アニメーションの仕組みを維持したままパラメータを統合するには、描画ロジック (`_draw_eye`) の大幅な変更や、より複雑な状態管理が必要となります。これはコードの可読性やメンテナンス性を低下させるリスクを伴います。

## 4. 提案

以上の分析に基づき、2つの案を提案します。

### 提案A: リファクタリングを見送る (推奨)

- **理由**:
  現状の実装は、`openness` と `curve` を独立してアニメーションさせることで、意図した通りの滑らかな表現を実現しています。これらはアニメーションの観点からは不可分であり、現在の2パラメータ構成は合理的です。無理に統合するとコードが複雑化し、得られるメリットよりもデメリットが大きくなる可能性が高いと考えられます。
- **方針**:
  `EyeState` クラスの定義は現状のまま維持します。

### 提案B: `EyeState` の生成を簡略化するファクトリメソッドを追加する

- **理由**:
  クラスの構造には手を加えず、`MOODS` での状態定義をより直感的にするための代替案です。
- **方針**:
  `EyeState` クラスに、特定の状態を生成するためのクラスメソッド（ファクトリ）を追加します。
  ```python
  @dataclass
  class EyeState:
      # ... (既存のパラメータ)

      @classmethod
      def create_closed(cls, curve_value: float, size: float = 8.0):
          """
          閉じた状態のEyeStateを生成するファクトリメソッド
          """
          return cls(openness=0, curve=curve_value, size=size)
  ```
- **利用例**:
  - **変更前**: `EyeState(openness=0, curve=1)`
  - **変更後**: `EyeState.create_closed(1)`
- **評価**:
  このアプローチは、`MOODS` の定義の可読性をわずかに向上させますが、クラス自体の責務が少し増えることになります。根本的な解決策ではありませんが、妥協案として考えられます。

## 5. 結論

現時点では、**提案A（リファクタリングを見送る）**が最も合理的であると結論します。アニメーションのロジックを考慮すると、現在の2パラメータ構成は非常に理にかなっています。

この計画について、ご確認をお願いいたします。
ユーザーの承認が得られれば、今回はコードの変更を行わないこととします。もし、提案Bやその他のアプローチでの実装を強く希望される場合は、その旨をお知らせください。
