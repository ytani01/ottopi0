# 計画書: ottopi0単体テスト作成

## 1. 目的
`src/ottopi0/`ディレクトリ配下の全モジュールに対する包括的な単体テストを作成する。テストは`tests/`ディレクトリに配置し、`pytest`フレームワークを使用する。

## 2. 基本方針
- **フレームワーク**: `pytest`を使用する。
- **モック化**: 全ての外部依存およびハードウェア固有モジュール（例: `pi0servo`, `pigpio`, `requests`, `fastapi`, `blessed`）は、`unittest.mock`と`pytest-mock`を用いて徹底的にモック化する。これにより、実機や外部サービスがない環境でもテストを実行可能にする。
- **ファイル構成**: 各ソースモジュールに対応するテストファイルを`tests/test_XX_module_name.py`の命名規則で作成する。
- **カバレッジ**: 正常系、異常系、境界値を網羅するテストを作成し、高いコードカバレッジと堅牢性を確保する。
- **ソースコードの変更不可**: 既存のソースコードは一切変更しない。

## 3. モジュール毎のテスト戦略

### 3.1. `src/ottopi0/func_calc.py`
- **テストファイル**: `tests/test_01_func_calc.py`
- **戦略**:
  - このモジュールは外部依存のない純粋な計算関数を含んでいると見られる。
  - 通常の値、ゼロ、負の値、境界値など、様々な入力に対する計算の正しさを検証するテストケースを作成する。

### 3.2. `src/ottopi0/func_servo.py`
- **テストファイル**: `tests/test_02_func_servo.py`
- **戦略**:
  - このモジュールはサーボモーターを制御し、`pi0servo`や`pigpio`のようなハードウェア関連ライブラリに依存している可能性が高い。
  - `pi0servo.Pi0Servo`クラスと`pigpio`の関数をモック化する。
  - `func_servo.py`内の関数が、期待されるパラメータでモックオブジェクトを呼び出すことを検証するテストを作成する。
  - 初期化、動作コマンド、その他のロジックをテストする。

### 3.3. `src/ottopi0/rpcclnt_bt.py`
- **Test File**: `tests/test_03_rpcclnt_bt.py`
- **戦略**:
  - このモジュールはBluetooth入力を利用するJSON-RPCクライアントと思われ、Bluetooth通信のために`pibtinput`、RPC呼び出しのために`requests`に依存している可能性が高い。
  - `pibtinput.PiBtInput`クラスをモック化し、様々なBluetoothイベント（ボタン押下など）をシミュレートする。
  - `requests.post`メソッドをモック化し、RPCサーバーからの応答（成功および失敗ケース）をシミュレートする。
  - `blessed.Terminal`をモック化し、実際のターミナルなしでターミナル出力をテストする。
  - メインループ、イベントハンドリング、RPC呼び出しのロジックをカバーするテストを作成する。

### 3.4. `src/ottopi0/rpcsvr.py`
- **テストファイル**: `tests/test_04_rpcsvr.py`
- **戦略**:
  - このモジュールは`FastAPI`を使用してJSON-RPCサーバーを実装している。
  - `FastAPI`の`TestClient`を使用して、APIエンドポイントにシミュレートされたHTTPリクエストを送信する。
  - 依存関係にある`func_servo`モジュールをモック化し、サーバーロジックをハードウェア制御ロジックから分離する。
  - 各APIエンドポイントに対して以下の点を検証するテストを作成する：
    - 有効なリクエストに対する正しい応答。
    - 無効なリクエストに対する適切なエラーメッセージとステータスコード。
    - JSON-RPC 2.0プロトコル要件の正しい処理。

## 4. 実行
各モジュールのテストを実装した後、`pytest`を使用してテストスイート全体を実行し、全てのテストが成功すること、そして意図しない副作用がないことを確認する。
