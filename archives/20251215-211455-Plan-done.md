# リファクタリング計画

## 概要
tests/ディレクトリ内のPythonテストファイルを分析した結果、保守性、可読性、効率を向上させるためのリファクタリングの機会がいくつか特定されました。主な焦点は、コードの重複を減らし、共有フィクスチャをより効果的に利用し、テストの構成を改善することです。

## リファクタリング項目

### 1. CLI統合テストの共通部分の統合
CLIコマンドの統合テスト (test_10_cli_svr.py, test_11_cli_cmd.py, test_12_cli_bt.py, test_13_cli_webui.py) には、`CliRunner`のインスタンス化、CLIコマンドの呼び出し、および共通のアサーション (`result.exit_code`、`"Done." in result.output`、`"ERROR" in result.output`) に重複が見られます。

- **計画:** `tests/conftest.py`に`cli_runner`フィクスチャを作成し、`CliRunner`のインスタンスを提供します。また、共通のCLI呼び出しとアサーションをラップするヘルパー関数（例: `run_cli_command_and_assert`）を導入し、コマンドと期待される出力/動作をパラメータとして受け取れるようにします。

### 2. `test_07_webui.py`内のモック設定の改善
`test_07_webui.py`では、`ConfFile`と`CmdStrLib`の内部モック設定が複数のテストメソッドで繰り返されています。

- **計画:** これらのモック設定を`test_07_webui.py`内のフィクスチャに抽出し、各テストメソッドがそのフィクスチャを利用するように変更します。これにより、テストのセットアップが簡素化され、可読性が向上します。

### 3. `test_05_bt.py`内の`PiBtInput.KEY`設定の重複解消
`test_05_bt.py`の複数のテストメソッドで`mock_deps["PiBtInput"].KEY = {"up": 0, "hold": 2, "down": 1}`という行が重複しています。

- **計画:** この設定を`mock_deps`フィクスチャ内、または`mock_deps`が返すモックのセットアップの一部として組み込みます。これにより、冗長性が排除されます。

### 4. `test_04_svr.py`内の環境変数処理の改善
`mock_env_and_deps`フィクスチャで環境変数を手動で設定・削除していますが、`pytest-mock`の`mocker.patch.dict`を使用することでより簡潔に記述できます。

- **計画:** `os.environ`のモックに`mocker.patch.dict`を導入し、環境変数設定のクリーンアップを自動化・簡素化します。

### 5. その他の小さな重複と一貫性の改善
- 各CLIテストファイルにおける`CliRunner()`の重複インスタンス化: これは項目1の`cli_runner`フィクスチャによって解決されます。
- CLI出力の繰り返しアサーション: これも項目1のヘルパー関数によって解決されます。
- `Cmd`アプリのインスタンス化の重複 (`test_06_cmd.py`): これは`test_06_cmd.py`の専用フィクスチャに移動することで解決できます。

## 実施計画
1. `tests/conftest.py`に`cli_runner`フィクスチャとCLIヘルパー関数を実装します。
2. 上記のヘルパー関数を使用するように、すべての`tests/test_1*_cli_*.py`ファイルを更新します。
3. `tests/test_07_webui.py`内のモック設定を抽出するフィクスチャを実装します。
4. `tests/test_05_bt.py`内の`PiBtInput.KEY`設定を`mock_deps`フィクスチャに移動します。
5. `tests/test_04_svr.py`内の環境変数モックを`mocker.patch.dict`に更新します。
6. `tests/test_06_cmd.py`内の`Cmd`アプリのインスタンス化をフィクスチャに移動します。
7. すべての変更後、`mise run test`を実行して、すべてのテストがパスすることを確認します。
8. ユーザーに報告します。
